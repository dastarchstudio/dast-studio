# مدیریت کارکنان — نسخه بازبینی

این تغییر صرفاً در شاخه feature/admin-employee-management آماده شده است؛ migration اجرا نشده و به دیتابیس یا سایت عملیاتی دست زده نشده است.

## امکانات پیشنهادی
- API مدیرمحور برای فهرست، ایجاد و ویرایش پروفایل کارکنان
- ساخت حساب Supabase Auth از سمت سرور؛ رمز هرگز در رابط فهرست برگردانده نمی‌شود
- ثبت نام، ایمیل، سمت، گروه، کد فایل و وضعیت فعال
- جلوگیری از تغییر پرچم is_admin از endpoint
- رابط اولیه در /admin-employees.html

## پیش‌نیازهای بازبینی قبل از استفاده
1. تطبیق ستون‌های profiles با migration و داده‌های واقعی؛ ستون‌های هم‌نام/جایگزین را بررسی کنید.
2. اجرای migration فقط پس از بکاپ و تأیید جداگانه.
3. تکمیل سیاست غیرفعال‌سازی: ستون is_active به‌تنهایی ورود Supabase Auth را مسدود نمی‌کند؛ باید قبل از فعال‌سازی عملیاتی در مسیر ورود و مجوزهای API بررسی شود.
4. بازبینی سیاست‌های RLS، SECURITY DEFINER و سطح دسترسی کلید سرویس.
5. آزمون در Preview با حساب آزمایشی؛ تست با کاربران و داده‌های واقعی انجام نشود.
6. لینک‌کردن صفحه در ناوبری اصلی پس از بررسی جای مناسب و سطح دسترسی.

## محدودیت‌های فعلی
- این نسخه اولیه صفحه مستقلی است و هنوز به ناوبری اصلی اضافه نشده است.
- گروه دسترسی «مدیر/طراح/مالی/کارمند» فعلاً metadata پروفایل است؛ به‌تنهایی مجوزهای ریزدانه ایجاد نمی‌کند.
- به دلیل عدم اجرای migration و عدم تست زنده، سازگاری نهایی با schema فعلی تأیید نشده است.
